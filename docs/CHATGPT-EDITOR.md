# ChatGPT writing manager

The owner-private Site exposes `/mcp` with eight bounded tools: list pending writing or learning requests, read one writing or learning context, read an attachment linked to that item or lesson, and save an editorial proposal or learning analysis. Sites manages the private plugin and OAuth. Discovery carries no workspace data. Data-bearing MCP calls require a Sites-authenticated visitor ID with an unexpired administrator login recorded for that same visitor. A Site service token does not provide MCP visitor identity.

After publishing, use native Sites `get_site(include_mcp_connection: true)` and pass its exact plugin ID to `plugin_management.suggest_plugins`. An actual authenticated read is required to verify the remote connection. Publication and installation alone do not prove it.

The writer offers **ChatGPT 대화에서 작성** and the existing **사이트에서 바로 생성 (API)** separately. ChatGPT mode records the item, instruction, scope and optional selected range; it does not call the OpenAI API or pretend that background generation started. The user continues the request in the connected ChatGPT conversation. Requests can be canceled without deleting the item or draft.

The editing agent must read the user's real notes, fixed editing policy, active lessons, attachments and supplied links. Referenced experiences in style examples are never transferable to this item. Verify current official information using actual research tools and save sources separately. Never claim an unread PDF, blocked link or unverified experience was read or experienced.

Proposals require a content revision hash returned by the context tool and a request ID. Changed material rejects stale proposals. Repeated request IDs do not duplicate results. Saving never changes a draft, date, publication status, XP or external platform. Use the existing preview/apply/undo flow to apply the result; it continues to reject a stale draft or metadata change.

An owner agent in this conversation may also use the bounded `/api/editor-assistant` route while the Site is confirmed owner-private (sole viewer, no groups or external visitors). GET returns at most 30 unpublished item summaries and 20 pending requests, or one context selected by item ID. POST supports only reading one linked attachment or saving one proposal. Use a fresh native Sites service token only for this Site in the dispatch header, through hidden stdin; never print it or retain it in files. Browser access to this route still requires the administrator cookie. The route gives no access to connected apps, publishing or arbitrary workspace mutations. Never change the Site's audience to reach it.

This alternative uses the current ChatGPT conversation for composition. It does not replace an OpenAI API key for immediate, unattended generation inside the Site and does not establish Naver auto-publication.

The existing enabled daily reporting automation `Automation_999c803f3a7c8191ba794d264243e029` also processes up to two queued learning requests and two queued writing requests at 18:00 Asia/Seoul, then stores its daily report and Monday weekly review. It handles only actual saved requests; it does not apply drafts, change dates, or publish externally. Missing tools, unread files or inaccessible sources must be reported, never treated as successful completion. Registration is confirmed; the first scheduled run still needs verification. This uses the existing automation rather than adding another task.

Learning requests first save the actual modal fields and connected attachments. Analyses store summary, learning points and application separately with read-file IDs, checked URLs and warnings. Missing source evidence cannot be marked complete. Unread linked PDFs or inaccessible original links stay explicitly partial. Analysis saves preserve original material, the owner's active checkbox and fixed editing policy; stale material rejects a save. The owner-agent route also supports GET `?kind=learning`, GET `?lessonId=...`, and the two learning attachment/analysis operations. No arbitrary mutation endpoint is exposed.
